# DayPillar · 传统历法日历

品牌 Logo：正式采纳 [PR #2](https://github.com/chuyua/DayPillar/pull/2) 的 SVG 资产，页头显示 `public/brand/daypillar-logo.svg` 与中文“时序”字标，浏览器 favicon 使用同一图形。资产另含英文横向字标、墨绿单色与深色反白版本；尺寸、间距和色值参见 [品牌用法](docs/brand.md)。四张 SVG 保留原始矢量，不依赖外部资源；发布目录由 Vite 使用 Pages 项目子路径自动组织。

本项目是 `tyme4ts` 驱动的静态历法前端，与旧站 `https://tyme.pages.dev/` 并行，不会自动覆盖现网。

## 数据及授权边界

- 公农历、干支、节气、建除、黄黑道：统一由 `tyme4ts@1.5.4` 计算；不展示 Tyme 的 28 宿值日体系。
- 传统农历月日 **27 宿循环规则**：`src/data/stars.mjs` 内仅实现常见规则，**不包含**机构内部电子表格、完整导出数据、原件内容或原件指纹。
- 60 条 `GUA_YING` 对应关系：保留顺序、对应名称及 `/n` 分隔方式；按用户确认的六十甲子顺序与日干支匹配（甲子日为天风姤／天罡），在月历和详情中直接展示。按用户 2026-10-28 指示，两处卦名规范为「火雷噬嗑」（己亥日／甪端）和「山天大畜」（戊午日／九婴），其他 58 组不变。
- **保密：**机构内部《二十八星宿.xlsx》不得放进公开仓库、CI 缓存、构建产物、GitHub Pages 或 Release。禁止提交 `reference/`、`src/data/xlsx-stars.json`、生成原件脚本及传输文件。
- 内部电子表格可在受控环境中单独核验，但公开 CI **不访问**该原件，不代表已对原件进行在线回归验证。
- 闰月暂按同名农历月的 27 宿规则处理，该口径尚需单独研究，不强行视为历法库缺陷。

## 构建与部署

不要求维护者本地构建。每次推送 `main` 后，GitHub Actions 在 Ubuntu 24.04 + Node.js 22 上自动运行：

1. `npm ci`
2. `npm test`（27 宿规则、60 条映射、Git 隐私门禁）
3. `npm run test:integration`（真实 tyme4ts 农历、闰月、干支等 API）
4. `npm run typecheck`
5. `BASE_PATH=/DayPillar/ npm run build`
6. `node --test tests/dist.smoke.test.mjs`（Pages 资源路径冒烟检查）
7. 上传 `dist/` 并用 GitHub Actions 发布 Pages

本仓库已设为 Public，并已启用 GitHub Pages 的 **GitHub Actions** 部署方式。每次推送 `main` 都自动执行完整测试、打包及 Pages 发布；PR 仅验证，不部署。同时上传 `daypillar-static-site` 静态构建产物（保留 14 天）。

**线上地址：** https://chuyua.github.io/DayPillar/ （2026-10-27 首次发布成功，并已核对主页及 JS/CSS 返回 HTTP 200）。

## 功能

公历月历、农历、干支、十二建除、黄黑道、节气、公开 27 宿算法；不再展示 Tyme 28 宿；六十甲子卦象直接融入每个日历格（卦名及对应名称）及右侧选中日期详情（如甲子日：天风姤 · 天罡），不另外展示映射列表或独立页面；支持日期跳转、闰月说明、可分享日期链接。支持 1900—2100 年区间，今日以中国标准时间（UTC+8）计算。

交互：同月点击日期只更新选中状态与详情，不重建网格；同月日期计算仅保留一份缓存。日期格支持方向键、PageUp/PageDown（按住 Shift 按年）、T 返回今日。移动端选日打开可关闭的底部详情面板。日历支持简洁/详细模式，**两种模式均保留卦名与对应名称**，简洁模式仅隐藏建除及 27 宿的格内次要标注（详情仍保留）。依赖锁文件使用官方 npm registry，构建和发布在 GitHub Actions 执行。

针对 Issue #1 的继续优化：年月采用独立下拉框（1900—2100 年），手机可在月历上左右滑动换月，向下拖动详情面板顶部把手可关闭；日历上直接输入干支、宿、卦名或对应名称即可高亮匹配日期而不触发重新计算；选中日期详情新增根据公开八卦爻位绘制的六爻 SVG，并以不同色点配合文字区分黄道与黑道。SVG 仅为可视化，不擅自修改原始 60 条卦名和对应关系。

配色支持跟随操作系统自动切换深浅模式，浏览器主题色同步更新；深色配色覆盖主页面、日历格子、详情、筛选控件、六爻图及特殊状态。

日期详情的文化资料采用「卦象映射／异兽和神煞介绍」两个可切换类目：卦象以左侧六爻图、右侧卦名与原创短释呈现，覆盖现有 60 条映射（含「火雷噬嗑」「山天大畜」）。第二类目直接以原映射中的对应名称为键，在 `tgqmdj.cn` 的 `did=5、6、7、8、9、10` 词典目录中建立可追溯的原条目链接；**共 60 个名称、60 条独立介绍**，包括 17 条异兽／神兽、9 条奇门九星、5 条术数神煞、5 条神怪、2 条空亡名义，以及 10 条岁阳与 12 条岁阴纪名。资料中明确标注类别，**并非全都属于严格意义的神煞或直接出自《山海经》**，也不意味着选中日期实际出现该神煞；古籍通行名称和词典异写会在释义中并列说明，绝不直接改写原六十甲子关系。所有简述为重写，不批量转载词典全文。

### 前端交互与维护

- **查询**：输入日干支、卦象、宿或节气后，本月仍有高亮；可通过「上一个」「下一个」或在输入框按 Enter／Shift+Enter 跨月导航，逐月分批计算而非一次载入全部年份，支持范围 1900–2100 年。跳转到日期后 URL 同步更新。
- **日期历史**：点击某个日期或通过跨月搜索明确选中日期会创建浏览器历史项；键盘连续移动日期、普通上一月／下一月不生成大量历史项。返回／前进会恢复年月和选中日期。
- **显示偏好**：没有手动偏好时随屏幕宽度选择详细／简洁；手动切换后尝试安全保存到 `localStorage`，禁用存储时保持可用。手机默认保留日历格中的卦象及对应名称。
- **详情层级**：干支、卦象和宜忌直接展示；古法历注、27 宿及资料来源默认折叠，可键盘展开，并在选日时保留已打开的栏目状态。来源和文化使用限制统一在末尾。
- **样式与字体**：语义化主题色变量代替 245 个颜色编码变量，深色主题集中在一个媒体查询中；系统宋体／黑体回退栈不依赖下载字体，避免额外文件体积。今天格子有 `aria-current="date"`，六爻图的无障碍名称包含当前卦名。

### 古法月建与历注（多规则并列）

日期详情新增独立的「古法月建与历注」，按 **节令月干支与日干支** 推导阳建（月建）、阴建（月厌）、厌对、黄黑道和月内天罡／河魁；按 **最新中气** 单独推导十二月将。月建以「节」为界、月将以「中气」为界，二者不能混算。比如 2026-02-11 为寅月辰日，**金匮黄道与厌对并存**，但尚未到雨水，因此月将仍为「神后·子」；2026-02-23 则是「登明·亥」。寅月月内天罡在巳、河魁在亥，**月内天罡不等于十二月将的固定“辰＝天罡”，也不等于用户固定映射“甲子→天罡”**。不把多套规则简单加减判定吉凶。

资料年代严格区分：十二月将的名称与地支关系直接参照唐李筌《[太白阴经·卷十](https://zh.wikisource.org/zh-hans/太白陰經/卷十)》；月厌、厌对的唐《天宝历》佚文见清李光地《[御定星历考原·月厌](https://www.shidianguji.com/book/SK1618/chapter/1jursttq22522)》；黄黑二道参照《[御定星历考原·黄黑二道](https://www.shidianguji.com/book/SK1618/chapter/1jurstuq9gl55)》，天罡河魁参照《[御定星历考原·天罡河魁](https://www.shidianguji.com/zh/book/SK1618/chapter/1m2ba99sxl2cm)》。不能把所有后世校订成果冒充唐代原文。当前网站只有公历日期，没有准确时刻：节气、交中气当天按历法库的**日期级**结果展示，未精确到交接时分。结果只用于传统文化考据，不作为现实决策或吉凶保证。

日期详情新增来自 `tyme4ts@1.5.4` 的 `SixtyCycleDay.getRecommends()/getAvoids()` 传统宜忌资料，仅在选中日期时读取，不参与整月计算，供文化资料查阅。npm 包名统一为 `daypillar`，网站保留中文品牌“时序”。

CI 新增 Playwright 真实浏览器回归，涵盖日期按钮焦点、键盘、移动抽屉、日期边界、搜索、深色模式以及卦象与宜忌；复用 GitHub Ubuntu 24.04 预装的 Google Chrome，避免重复下载 Chromium 与安装 apt 依赖。GitHub Actions 也更新到 Node 24 兼容的稳定主版本。

本仓库为独立升级实现，**尚不等同于旧站全量功能迁移**。没有旧站原始 HTML 与 JS 源码时，无法承诺旧版个人化运算已逐项完成迁移。
